── WHAT IS STELLA? ─────────────────────────────────────────────────────

Stella is an AI operating partner built specifically for the SiriusXM
Client Services team. She lives at a single URL — no installation, no
IT dependency — and is accessible to any SXM AM through their existing
Google account.

The goal: give AMs one place to manage campaigns, get instant answers
to billing and workflow questions, and eventually automate the repetitive
parts of the job that eat up time every day.

Stella is named after the SiriusXM mascot — Sirius, the Dog Star.


── HOW IT'S BUILT ──────────────────────────────────────────────────────

  Platform:     Google Apps Script (GAS) — deploys as a web app within
                Google Workspace. No servers to manage.

  Database:     One Google Sheet, one tab per AM. Auto-created on first
                login. 23 fields per campaign row.

  AI:           Claude (Anthropic) via SiriusXM's internal LiteLLM
                endpoint. API calls run browser-side so the internal
                hostname is reachable without a proxy.

  Architecture: Single-file SPA (Index.html) served by GAS. All CSS,
                HTML, and JavaScript in one file for easy deployment.
                Backend files (Stella.gs, StellaDB.gs, BillingKB.gs)
                handle the server-side logic — system prompt assembly,
                KB routing, and all Sheet reads/writes.


── WHAT'S LIVE TODAY ───────────────────────────────────────────────────

  CAMPAIGN DATABASE
  Each AM has their own tab in the shared Sheet. Campaigns track:
  opportunity name, Slingshot/OMS IDs, sales rep, start/end dates,
  campaign status, flight status, pacing %, traffic/reporting/misc
  tickets, notes, Salesforce URL, IO Case URL, launch date, additional
  tickets, structured flight dates, DAM folder URL, Ad Ops Castle URL,
  and 1P/3P billing flags.

  Key behaviors:
  - Add, edit, delete campaigns via a modal form.
  - Structured flight date picker (add individual start+end pairs).
  - Per-section inline edit on detail view — update just pacing,
    platform IDs, or a ticket without opening the full modal.
  - Auto schema migration: new DB columns added to existing AM tabs
    silently on load so no manual Sheet work is needed.

  AI ASSISTANT (STELLA)
  Powered by Claude. Available as a popup from any screen, and as an
  inline chat panel on every campaign's detail view (pre-loaded with
  that campaign's full context).

  Stella's knowledge base is dynamic — billing questions automatically
  pull in the full Billing Workflow KB covering IO approval, OMS setup,
  billing close, CBS/custom billing, make-goods, 3P reporting,
  discrepancy review, and prepay. More KB domains coming as subagents
  are built.

  Daily morning briefing: once per day on load, Stella computes campaign
  health (flight warnings, low pacing, untrafficked campaigns) and fires
  a live LLM call so she can write the briefing in her own voice. Appears
  as a dismissable banner on the dashboard and as the opening message in
  the popup chat that day.

  CAMPAIGN MANAGEMENT
  - Card grid view and sortable list view (toggle, preference saved).
  - Filter bar: ALL / LIVE / UPCOMING / ENDING SOON / ENDED.
  - Campaign detail: pacing bar, all platform links (auto-constructed
    from IDs), JIRA/Theorem ticket links, structured flight dates,
    billing flags, and flight warnings (7 days before end).
  - Per-section inline edit on detail view — update pacing, platforms,
    or tickets without opening the full modal.
  - Seller view: AMs share a read-only link with their sellers.
    No edit controls, no Stella chat. "Copy Seller Link" in sidebar.

  HOME DASHBOARD
  Seven customizable widgets, drag-and-drop reorder, individual close
  buttons. Widgets:
  - Campaign Calendar — Gantt chart (today ±90 days) with color-coded
    status bars. Toggle to compact sortable list view.
  - Campaign Activity — notification feed of alerts (flight warnings,
    low pacing, untrafficked campaigns). Per-item clear button. Click
    any alert to see campaign quick-links popup.
  - To-Do — personal task list with optional due dates and campaign
    tie-ins. Checkbox marks done (strikethrough). Auto-archive setting.
  - Quick Links — Ads Manager, #fyi-all Slack, The Hub, ARIA,
    CenterStage. Per-link show/hide.
  - CS Tools — 7 Hub tools: Ratecard, Podcast Explorer, Audience
    Discovery, Agency Ratecard, Vendor Matrix, Specs Generator,
    CS One Resource. Per-tool show/hide.
  - Meetings — Placeholder (Outlook integration planned).
  - Stella Runner — Pixel art endless runner mini-game.

  VIRTUAL OFFICE
  Six agent desks (Billing, Stella, Trafficking, Reporting, Handoff,
  Tagging). Toggle between pixel-art canvas view and flat card view.
  Clicking a desk opens a side chat. Stella's desk is live; others show
  roadmap status.

  RESOURCES TAB
  Dedicated page showing Quick Links, CS Tools, and user-added custom
  resources in a card grid. AMs can add, edit, and remove their own
  resources (label, URL, description, emoji icon, color). Saved to
  localStorage.

  SETTINGS
  Dark/light mode, six accent colors, default campaign filter, widget
  show/hide toggles, archive settings for campaigns and to-dos.
  "Restart Tour" button for demos. All persisted per device.

  ONBOARDING
  First-time users see a name capture modal (Stella asks what to call
  them), followed by a Stella intro and an offer to take a guided tour.
  The 6-step tour spotlights each nav section with a tooltip explaining
  what's live and what's coming. Nickname used in all greetings and
  briefings. Tour restartable from Settings for demos.

── WHAT'S NEEDED TO GO FURTHER ────────────────────────────────────────

  No blockers for current features — Stella is fully deployed and in use.

  Next-tier work requires one or more of:

  - API access to Slingshot / Ads Manager — for live pacing data and
    order sync (Items 6, 10). Needs IT or engineering to expose an
    internal endpoint, or direct API credentials.

  - Salesforce Connected App — for IO approval state, case list, invoice
    data (Item 7). Needs SF admin to set up OAuth + Connected App.

  - Knowledge base content from other AMs — to port the trafficking,
    monitoring, and upsell GPTs into Stella (Items 20–22). No technical
    work needed until the content is shared.

  - Internal server / proxy — to enable server-side streaming, remove
    API key from browser, and support multi-agent chaining (Item 16).
    Small lift for an internal engineering resource.

  - Outlook access — for email-based case/ticket notifications (Item 8).
    Medium-term path uses forwarding rules (no IT); long-term uses
    Microsoft Graph API (needs Azure AD app registration).
